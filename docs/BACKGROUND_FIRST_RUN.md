# 后台实验入门：场景、进度和成绩

本文承接[快速开始](QUICKSTART.md)：已获取依赖、完成算法构建，并在主仓库根目录执行命令。完整参数与评分定义见[实验指南](EXPERIMENTS.md)，本文帮助首次运行者判断当前正在做什么。

## 后台运行会显示什么

`experiment suite` 自动运行模拟器、算法与评分流程；后台实验通过报告查看结果，不要求打开桌面或三维交互窗口。终端打印任务信息后，带 `--wait` 的命令会继续等待完成，期间没有持续输出本身不能说明程序卡住。

提交返回值中的 `job_id` 是任务标识，`items` 是本次提交的实验项数量。`submitted` 表示任务已提交，运行状态应通过任务查询确认；它不表示算法已完成识别或实验已通过。

保留等待实验完成的终端，在另一个终端进入同一主仓库，用实际任务 ID 替换下面的 `job_实际ID`：

```bash
./sim.sh jobs status job_实际ID
./sim.sh jobs logs job_实际ID --tail 100
```

|任务状态|如何理解|
|---|---|
|`queued` / `running`|任务正在等待调度或执行，继续查看状态和日志|
|`completed`|任务调度完成，接着检查报告、证据有效性及实际发射数|
|`paused`|先查失败原因和保留的尝试记录，再按实验指南处理恢复|

查询状态和日志不会再提交一个实验。已有调度器时沿用该服务，避免为查询进度重复启动调度器或重复提交 suite。

## 先列出场景，再选择运行范围

以下命令只列出项目，不启动模拟器：

```bash
./sim.sh experiment suite --tier basic --list
./sim.sh experiment suite --tier advanced --list
./sim.sh experiment suite --tier basic --cases hf_static_5 --list
```

基础场景使用具体名称选择，例如 `hf_static_5` 为静止目标，`hf_uniform_3` 为匀速平移。进阶选择方式及运动含义见[项目列表](EXPERIMENTS.md#选择项目)。

快速开始首轮命令中的 `--tier basic --cases hf_static_5` 只运行所选静止场景；仅使用 `--tier basic` 而不限定 `--cases` 会选择整套基础场景。软件渲染较慢，第一次建议按快速开始的单场景命令验收。

`--sensor-seeds` 选择传感器噪声种子；保持相同场景与种子便于前后配对。重复相同种子主要用于检查重复性，不应当成多个独立噪声样本。换传感器种子也不等于改变运动轨迹。

## 分开理解现实耗时、仿真时间和成绩

后台 lockstep 可以慢于实时。场景的仿真计分时长与现实运行耗时不同；现实中等待较久，并不等于目标在仿真世界里多运动了同样长的时间。准备、图像渲染、算法处理与收尾都会占用现实时间，不能把整轮耗时当成单帧算法推理耗时。

报告提供多项指标，不将它们自动合成一个总分：

|指标|读报告时要区分的含义|
|---|---|
|精确命中率|有效目标装甲命中数 / 总发射数|
|中心加权命中率|命中位置越接近装甲中心，单发权重越高；全部命中也可能低于 100%|
|命中/秒、加权得分/秒|使用仿真计分时长，帮助判断是否靠少开火维持高命中率|
|`all_evidence_valid`|证据检查是否有效，不表示算法已获得提升|
|`within_cost_budget`|40 秒成本目标是否满足，与证据有效性分别报告|

零发射时命中率保持 N/A。验收首次射击链路仍须执行快速开始中的 `complete`、`all_evidence_valid` 和总发射数检查，不能只看任务完成状态。

报告文件位于提交时 `--output` 指定的目录，例如 `exports/first-static/report.md`、`report.html` 和 `results.json`。细分结果、运行标识与难度信息见 `results.json`；逐轮证据保留在本地实验目录，媒体导出与查看方法见[本地视觉对照](EXPERIMENTS.md#本地视觉对照)。

## 开始修改算法以后

先保存原版结果，再按[开发指南](DEVELOPMENT.md#修改算法)修改与重新构建。改后使用新输出目录，并保持环境、渲染后端、场景和种子一致，通过[两版对照](EXPERIMENTS.md#两版对照)检查配对条件和变化。

CPU 与 GPU 渲染可能生成不同像素；改用 GPU 后应在该后端重新建立基线。正式比较同时检查命中质量、吞吐、场景退步和证据有效性，完整保留失败与低分记录。代码提交、子模块引用更新及服务器实验申请按[贡献指南](../CONTRIBUTING.md)执行。
